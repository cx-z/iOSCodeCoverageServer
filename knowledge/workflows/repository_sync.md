# Registered MR repository synchronization

1. **Entry:** automatic service startup and a 60-second periodic sweep; Cycle creation/reuse queues an immediate request. Only persisted Cycles with an MR are discovered. Closed MRs are not fetched and remain discoverable if later reopened. No browser request is required.
2. **Call chain:** `ProbeHTTPServer` lifecycle -> `server/repository_sync.py` (`RepositorySyncService`) -> CoverageStore Cycle reads -> registry-bounded GitLab MR GET -> `integrations/git_sync.py` (`GitRepositorySynchronizer`). The returned project/IID must match the Cycle. Every sweep fetches both branch tips, even if MR head/diff refs are unchanged, so target-only pushes are not missed.
3. **Repository selection:** Cycle.project -> startup-fixed ProjectRegistry repository. `origin` must identify the same registered GitLab host and project using HTTPS, SSH URL, or SCP-style SSH. The server uses existing noninteractive Git read credentials, never its GitLab API token. Both source and target branches must exist in that origin; unregistered/fork remotes are not guessed.
4. **Writes:** explicit source/target refspecs populate only `refs/ioscoverage/branches/<branch-name-hash>`. Exact MR base/start/head and requested Build SHAs are checked as commit objects and retained under `refs/ioscoverage/commits/<sha>`. Missing exact objects get a bounded SHA fetch; unavailable objects fail safely. `--refmap=` suppresses configured remote-tracking side updates. HEAD, worktree, index, local branches, ordinary remote refs and FETCH_HEAD are unchanged. No tags, pruning, submodule recursion or automatic maintenance runs.
5. **Build registration repair:** the route first uses the unchanged storage validation. Only `git_object_not_found` queues a priority repair and waits up to 120 seconds, outside the store mutation guard. The same manifest and untouched streams are retried once. All immutable Git/merge-base/artifact checks still apply. Sync failure returns a safe HTTP 503 and publishes no Build. Other validation failures never cause fetch.
6. **Concurrency/lifecycle:** one worker serializes Git writes. A condition protects the queue and coalesces identical queued/running requests; network, Git and SQLite work run outside it. Startup/polling failures are isolated per request and retried on a later sweep. Every Git command has a 30-second deadline and owns a cancellable process group; shutdown cancels/joins the worker before service ownership is released. Unproven child termination prevents successful close and further Git commands. GitLab GET retains its existing 10-second timeout. Git output/remote URLs/credentials never enter responses or logs.
7. **Unchanged identities:** no schema change, Cycle head/base update, Build/Run mutation, LLVM scheduling or report rewrite. Synchronization supplies objects for the existing fixed-SHA consumers. The MR resolver and analyzers remain read-only. Existing transient MR presentation caches recover under their normal bounded retry.

Discovery uses `CoverageStore.list_repository_sync_cycles`, a minimal persisted-identity read without registry-dependent display projection. Each queued Cycle then passes the usual registered-project validation individually. Historical Cycles from removed projects fail only their own requests and do not prevent healthy startup/periodic synchronization; ordinary list/detail behavior is unchanged.

The Git command environment preserves `core.sshCommand`, `GIT_SSH_COMMAND` and `GIT_SSH` selection and arguments. New process sessions with DEVNULL stdin provide no controlling terminal; Git terminal prompting and credential-manager interaction are disabled, Git/SSH askpass are set to the failing `/usr/bin/false` helper, and `SSH_ASKPASS_REQUIRE=never` disables SSH askpass requests. Existing noninteractive credential helpers remain available. The command deadline and process-group cancellation still bound a slow transport.

Build repair passes lowercase snapshot identities, matching storage validation, while retaining the exact original manifest and its hash. Uppercase/mixed-case input remains accepted under the existing contract.

Tests: `tests/integrations/test_git_sync.py`, `tests/server/test_repository_sync.py`, and the real-artifact missing-object HTTP regression in `tests/server/test_api_contracts.py`.
